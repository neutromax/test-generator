## 1. One-Paragraph Summary

We are building an application that takes a GitHub repository and automatically produces test specifications and runnable pytest tests for it. It has two generation engines: **VIO** (the company's online multi-agent gateway, five specialised AI agents running in parallel) and **Ollama** (local AI models that run on our own machine, used because external AI APIs are restricted). The VIO path is complete and tested on three repositories. The Ollama path works end to end and was rebuilt this week to behave more like a real tester, but its generated tests do not yet pass reliably. Improving that pass rate is the main work ahead.

## 3. What Was Built

### 3.1 Application (shared)
- Web interface where a user pastes a GitHub URL; the app validates it, clones the repository and generates a test prompt.
- Choice of engine (VIO or Ollama) and of test category: unit, integration, end-to-end, API, security, vulnerability, linting.
- Results screen with per-test outcomes, downloadable reports and a dark/light theme.
- Code size (measured): about 3,050 lines in `app.py`, plus supporting modules under `src/`.

### 3.2 VIO engine (company multi-agent gateway)

| Agent | Role | Test types it handles |
|---|---|---|
| test_generation_master | Supervisor: quality review and final report | Validation, summary |
| test_unit_generator | Worker | Unit, linting |
| test_integration_generator | Worker | Integration |
| test_e2e_generator | Worker | End-to-end, API |
| test_security_scanner | Worker | Security, vulnerability |

What it does:
- Connects to the gateway with credentials held in a local `.env` file (not stored in code).
- Runs the worker agents **in parallel** (up to four at once) in a background thread, so the screen stays responsive while generation runs.
- Master agent grades each generated test (GOLD / SILVER / BRONZE) and writes a consolidated final report.
- For every agent, saves the exact prompt, the generated script and a plain-language README. If a test fails, the README explains why it failed and suggests a fix.
- Installs the target repository's dependencies, then runs the generated tests with pytest.

### 3.3 Ollama engine (local models)
- Three local models are routed by task: Qwen 2.5 Coder (code), Llama 3.1 (reasoning and security), Gemma 3 (end-to-end and balanced tasks).
- Works with no external API, which is the main reason it exists.
- Rebuilt this week into a **specification-driven workflow**: for each public function or class in the repository, the tool creates a numbered specification (001, 002, ...) and a matching test script. The number of test scenarios follows the component's complexity rather than a fixed count.
- Safeguards added: automatic retry when the model returns invalid Python, rejection of placeholder or skipped tests, a check that every planned scenario has a matching test, and a check that tests import and exercise the real code instead of copying it.
